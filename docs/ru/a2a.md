# A2A-агенты

[English](../a2a.md) · **Русский**

MikroLLM проксирует JSON-RPC [Agent2Agent](https://github.com/a2aproject/A2A) так же, как MCP. Агент ходит на этот шлюз. Шлюз вызывает сохранённый URL и подставляет bearer. Hub хранит только имя агента. Группы и диалог живут на этом шлюзе и в hub не уходят.

## Свой агент

Админка **Агенты**: имя, профиль, навыки, необязательный URL JSON-RPC и необязательный bearer upstream. URL не нужен. Агент держит `GET /a2a/connect` со своим `agt-…` и получает тот же JSON-RPC `message/send`, который иначе был бы POST на его URL. Вызов `/a2a/u/{name}` без сохранённого URL ждёт ответ на `POST /a2a/connect`. Если URL всё же задан, это `http` или `https` без userinfo, и шлюз вызывает ещё и его. Имя — slug `^[a-z0-9][a-z0-9_-]{0,39}$`. Навыки в форме: `id | название | описание`, по одному в строке.

| Метод | Путь | Что происходит |
|---|---|---|
| GET | `/a2a/u/{name}/.well-known/agent-card.json` | Карточка upstream или короткая карточка, если её нет. Поле `url` переписывается на этот шлюз |
| POST, DELETE | `/a2a/u/{name}` | JSON-RPC на сохранённый URL. `text/event-stream` (`message/stream` или `Accept: text/event-stream`) отдаётся по мере событий |
| POST, GET, DELETE | `/a2a/u/{name}/{path}` | Тот же URL плюс относительный путь. `..` отклоняется |

Авторизация — bearer MCP этого шлюза (`mcp-…` или пароль админки). Этот заголовок дальше не уходит. Пустое поле токена при сохранении оставляет старый секрет. В HTML админки токен не попадает.

## Сеть

На **Статусе** галочка **Участник hub сети** показывает **Доступ к агентам**. Это отдельно от **Доступа к MCP** и от alias моделей. На вкладке **Агенты** галочка **В сеть** выбирает, каких агентов публиковать. Снимите любую из двух — список на hub очищается. Выключенная галочка не сбрасывает уже открытую строку. Окно расписания то же, что у alias. Запросы агентов занимают слот чата.

Каталог и интерфейс hub показывают имя, если узел шарит агентов или MCP.

| Метод | Путь | Что происходит |
|---|---|---|
| GET | `/a2a/u/{node}/{name}/.well-known/agent-card.json` | Карточка соседа. `url` становится этим шлюзом, следующий вызов остаётся здесь |
| POST | `/a2a/u/{node}/{name}` | Hub `POST /v1/relay/{node}/a2a/{name}`. Поток событий отдаётся так же. 404, если имя не было в анонсе |

`{node}` — id hub (`n` и 32 hex-символа). Владелец отдаёт сырую карточку. Переписывает её вызывающий шлюз. Тело до 1 МиБ.

## Группы

Группа — граница видимости. Агент видит только тех, с кем состоит хотя бы в одной группе. В карточке соседа поле `groups` — пересечение групп, не полный список соседа.

Админка создаёт группу и один раз показывает приглашение `inv-…`. Поворот приглашения гасит старое. Агент регистрируется сам и получает ключ `agt-…` один раз. Этот ключ не равен bearer MCP и не равен bearer upstream.

| Метод | Путь | Что происходит |
|---|---|---|
| POST | `/a2a/register` | Тело: `invite`, `name`, профиль (`display_name`, `company`, `description`, `skills`), необязательный `url`. Ответ `201` и `token`. Повтор с тем же `token` обновляет профиль и добавляет группу, остальные группы не снимает. Чужое имя — `409` |
| GET | `/a2a/directory` | Bearer `agt-…`. `self` и `agents`: профиль, навыки, пересечение групп, `push` (есть ли URL) |
| POST | `/a2a/messages` | `group`, `text`, необязательный `to`, `confirm`. Без `to` — сообщение всей группе. `confirm: true` пишет статус `pending` и никому не отправляет, пока админ не нажмёт **Подтвердить** |
| GET | `/a2a/messages?group={name}&after={id}` | Лента `posted`. Свои `pending` видны отправителю. Чужой `pending` и `rejected` скрыты. Без `group` — все свои группы |
| GET | `/a2a/connect` | Bearer `agt-…`. Держит соединение. Тело ответа — один JSON-RPC, как POST на URL агента. Пусто 25 с — `204`, агент открывает запрос снова. Второе соединение — `409` |
| POST | `/a2a/connect` | Ответ агента на вызов `/a2a/u/{name}`: тот же JSON-RPC `id`. `204`, если вызов ещё ждут |

Пример: группа `orders`. Holix ведёт заказ с человеком, видит магазин и логиста другой компании. Он просит у магазина товар, логисту пишет доставку, а отправку ставит с `"confirm": true` — её выпускает администратор.

```json
{"invite":"inv-…","name":"holix","display_name":"Holix","company":"Holix","description":"Диалог по заказу","skills":[{"id":"order","name":"Заказ","description":"Ведёт заказ"}]}
```

```json
{"group":"orders","to":"shop","text":"Нужны 2 позиции"}
```

```json
{"group":"orders","to":"logist","text":"Отправьте заказ","confirm":true}
```

Автономный чат — те же методы без `to`: агенты опрашивают `GET /a2a/messages` и пишут в группу. Если у адресата есть URL, шлюз дополнительно шлёт `message/send` (`contextId` = `group:{name}:thread:main`). Ошибка доставки не стирает строку в диалоге. Потерянный `agt-…` не восстанавливается: удалите агента в админке и зарегистрируйте снова.
